1. **Make verification the primary action.** A reader should be able to go from a claim to the exact supporting passage and back without losing their place. Put “Check source” beside the quote; distinguish the printed page from the PDF page number when they differ. Give each excerpt a stable, citable URL. Show the caveat most likely to change the reader’s interpretation beside the finding, not below the quality table.

2. **Don’t turn quality checks into a verdict.** A strong/weak count gives minor reporting omissions and serious validity problems equal weight. Default to a short list of consequential findings with one-line rationales; group the full checks by domain. Distinguish “not reported,” “not applicable,” and “judges disagree.” Where judges disagree, show their reasoning rather than averaging it away. Label assessments as model-generated unless a person actually verified them; a prompt link is provenance, not validation.

3. **Make relationships readable without the graph.** Use links that say what they do: “Supports this claim,” “Limits this finding,” “Other evidence from this paper.” Give evidence pages links back to every claim they support so readers arriving from search have context. Use plain-language page types in navigation and search; keep IDs for lookup and citation. Show result type and matched text so readers can distinguish a paper from an assessment of it.

4. **Design narrow layouts around reading order.** Don’t simply stack the desktop rails: keep the finding, source link, and decisive caveat together, then offer a compact “On this page” disclosure for long pages. Collapse navigation when the links no longer fit, not at an assumed device width. Underline prose links, reserve the smallest type for secondary metadata, and test muted text, status chips, and focus rings against actual surfaces in both themes. Never encode judgment by color alone.

5. **Specify focus behavior, not just keyboard coverage.** In search, keep focus in the input while arrows move the active result; announce result counts and no-results states. Escape should dismiss the dialog and return focus to its trigger. Make figure zoom a labeled button and return focus on close. Ensure sticky UI never covers focused controls or anchor targets. Cut the resize handle unless it solves a demonstrated problem.

6. **Make the graph optional, not a second interface readers must learn.** The list should expose the same nodes, relationships, and filters. Highlight selection in both views without stealing focus or auto-panning. Keep layout motion out of the reduced-motion experience and load the canvas only when requested. Test whether someone can answer “What else supports this?” from the list alone.

7. **Make the evidence usable on slow connections and in print.** Deliver quotes, caveats, and source links in the initial HTML. Load screenshot thumbnails separately and full-resolution images on demand; preserve captions and source links if images fail. Set a transfer budget for a cold mobile evidence-page visit. Print the excerpt, decisive caveats, citation, and stable URL; omit navigation and graph UI.

8. **Move validation into each phase.** Before rollout, watch researchers trace a claim, interpret a disputed check, and export a citation. Repeat those tasks with keyboard and screen reader on representative pages. Use CI for regression checks, but manually test focus restoration and whether the evidence hierarchy makes sense when read aloud. Defer the inbox until reviewers demonstrate a recurring need to track unfinished checks.
