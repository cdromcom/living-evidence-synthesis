## LIVES redesign: two pages

**What it is.** LIVES (Living Evidence Synthesis) is a public site of about 232 linked pages that answers one question: can large language models help review scientific papers? Page types: Questions (QUE) are answered by Claims (CLM), which rest on Evidence (EVD) from Source papers (SRC); Caveats (CVT) limit the evidence; Patterns (EP) group evidence across papers. Every EVD shows a verbatim quote with its printed page and a screenshot of the paper, plus quality signals (about 35 checks such as TRIPOD-LLM reporting, validity, rigor, openness). Readers: researchers and reviewers who want to check a claim down to the source sentence. Every page ends with a clean AI-use footer following the GAMER checklist (a medical-research checklist for reporting generative AI use): closed, one line ("AI use: models, date, human-check status"); opened by click, hover or keyboard, a skimmable table of step, model and version, effort, time, prompt link and saved response, linked to a project-wide disclosure page. A byline under the title repeats the one line.

**Today.** Next.js (App Router, static pages), Tailwind v4, Vercel, a force-directed graph (react-force-graph-2d, canvas), search palette, light and dark themes, a cream and forest palette, serif headings with sans body and mono IDs. The audit found a skip link, a global focus ring, a mobile menu and reduced-motion handling already in place; the gaps are: a 2 MB data file shipped to every page, the search dialog has no focus trap or arrow-key results, the graph canvas is not keyboard operable (a node list is the alternative), the fonts load from Google, tooltips and figure zoom need keyboard parity.

**Direction chosen ("A, Refined Journal", evolve in place, not flashy).** Same look, stricter type scale (0.75, 0.875, 1, 1.125, 1.5, 1.875, 2.5 rem), 4 px grid, 6 px radius, borders not shadows, one focus style (2 px ring, 3:1), medium density, 70-character article measure. Decisions: top bar with all links and a menu button below 768 px; dark mode kept with a remembered toggle; keep the graph library and add a synchronised node list with full keyboard parity; keep the markdown pipeline and add snapshot tests; plain Tailwind tokens and hand-written primitives (Field, Button, Chip, Callout, Disclosure), Radix only for Dialog, Popover and Tooltip.

**Keyboard requirement.** Everything works without a mouse: skip link, menu, search as a combobox (arrows, Enter, Esc), node-page table of contents, disclosures, figure zoom, sortable tables, the graph through its list, forms, the resize handle. No single-key shortcuts at first. Tested with Playwright keyboard scripts, axe in CI, a screen-reader pass before release.

**Node page (the product).** Three columns on wide screens (table of contents, article, review and links rail), one column below 1024 px. Order in the article: headline finding with its decisive caveat beside it, quote and screenshot, methods context, quality signals as domain rows (Adequate, Concern, Not reported, Not applicable, Judges split; no strong/weak tally), caveats, references, then the AI-use footer.

**Color.** Cream background, forest green accent, ink text; colorblind-safe categorical palette (Okabe-Ito) for node types and quality statuses, never color alone (each status also has an icon and a word). Contrast target 4.5:1 text, 3:1 UI. Dark mode keeps the same hues, not inverted. Tokens as CSS variables on `:root` and a dark override.

**Typography.** Serif headings, sans body, mono for IDs and quotes in a distinct quote style. Self-hosted fonts (no Google request), two weights per family, `font-display: swap`, a 70-character measure, line height 1.6 for body and 1.25 for headings, tabular numbers in tables and metrics. A quote block carries its printed page as a small label.

**Layout and spacing.** 4 px grid, spacing scale 4/8/12/16/24/32/48/64, three columns above 1280 px, two from 1024, one below; sticky table of contents; a table that does not fit scrolls inside its own region with a visible focus ring; sizes of touch targets at least 44 px on mobile.

**Visuals.** The screenshot of the source (with the quote highlighted) is the hero of each evidence page; figures zoom with keyboard and pinch; the graph is a secondary view (list first, canvas loaded on demand); small inline marks (node-type glyphs, quality icons) from one icon set; no decorative illustration.

**Animation.** Minimal: 150 ms ease for hover, focus and disclosure; no scroll-jacking or parallax; every motion respects `prefers-reduced-motion`; graph physics paused for reduced motion; page transitions only move focus to the h1.

**Accessibility.** WCAG 2.2 AA target; skip link, landmarks, focus on the h1 after route change, visible focus (2 px ring), combobox pattern for search, details/summary for disclosures, popovers instead of hover-only tooltips, alt text for every screenshot that restates the quote, tables with proper headers, print stylesheet, axe and Playwright keyboard tests in CI, a screen-reader pass before release.

**Build plan.** Five phases, each shippable: (1) tokens, primitives, data split so only a small index reaches the browser; (2) header, menu, skip link, search combobox; (3) node page layout and quality-signals table; (4) graph list with keyboard parity; (5) tests and CI. Built by Claude Opus 5.5 (Sonnet 5.5 for tests), reviewed by a model from another family, with the owner approving each phase. Budget about $50 to $100 of model cost.

**Open questions.** How much of the 35 quality signals to show by default; how to show uncertainty and disagreement between AI judges without overwhelming readers; whether reviewers need an inbox view; print and citation styles; what to do for readers on slow connections.
