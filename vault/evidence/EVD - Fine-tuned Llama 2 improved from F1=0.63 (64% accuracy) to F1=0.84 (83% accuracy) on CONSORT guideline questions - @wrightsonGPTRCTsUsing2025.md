## Description

## Methods Context

### What?

> **Study design:** within-model before/after comparison of an open-source LLM on the same TEST split used for the GPT-4 Turbo benchmark; designed to test whether a locally-runnable model can match closed-source performance.
>
> **Method type:** zero-shot baseline vs. supervised fine-tuning on synthetic labels generated by GPT-4 Turbo on the TRAIN split (i.e., distillation/self-training-style supervision rather than direct human labels).
>
> **Tools:** Meta **Llama 2 70B** (open-source, hosted on the TogetherAI platform (San Francisco, USA) for both inference and fine-tuning); TogetherAI playground default hyperparameters at evaluation time (temperature=0.7, Top P=0.7); same Schulz et al. 2020 ground-truth labels.
>
> **Dependent variables:** pooled F1-score and pooled classification accuracy (95% Clopper–Pearson CI) across 8 CONSORT text questions × all TEST papers; reported pre- and post-fine-tuning.
>
> **Independent variables:** training condition (base Llama 2 70B vs. fine-tuned Llama 2 70B); the 8 CONSORT items used (question 9, "standardised effect sizes & CIs," excluded, combining Method + Results exceeded the Llama 2 context window).
>
> "We also tested the open-source Llama 2 AI-LLM. We included an open-source model because we envisage use cases where authors may want to run models locally or wish to support open-source systems in accordance with open science principles. … The analysis of the TEST dataset using the base and fine-tuned Llama 2 models was performed using the TogetherAI playground using the platform default hyper-parameter values (temperature and Top P=0.7)." (Wrightson et al., 2025, p. 4)
> ![[wrightsonGPTRCTsUsing2025-evd-p4-1.png]]

### How?

> **Procedure:** (1) Reuse the same 113-paper / 80-20 TRAIN-TEST split, stratified by paper section, used for GPT-4 Turbo. (2) For the **base** condition, prompt Llama 2 70B with the same engineered system + user prompts as GPT-4 Turbo (response cap 512 tokens). Because the Llama 2 context window cannot fit a Method + Results concatenation, **drop CONSORT question 9** entirely; submit 8 (paper-section, question) pairs per paper. (3) For the **fine-tuned** condition, take only the **TRAIN** examples that GPT-4 Turbo answered correctly and use them as Llama 2 fine-tuning data (i.e., GPT-4 outputs serve as labels for distillation), via the TogetherAI fine-tuning workflow. (4) Re-evaluate the fine-tuned Llama 2 70B on the TEST split using the TogetherAI playground defaults (temperature=0.7, Top P=0.7). (5) Compute pooled F1 and pooled accuracy with 95% Clopper–Pearson CIs in R 4.3.2. The fine-tuned model's confusion matrix is reported in Supplementary Figure S2. No formal McNemar's / paired test between base and fine-tuned reported in the main text.
>
> "The Llama 2 model was fine-tuned using the correctly answered questions from the GPT-4 analysis of the text training data. One of the reporting guideline items could not be included in this analysis (table 2, question 9) because this question required the text from the method and results to be passed to the model, exceeding the number of tokens allowed in the context window. The tuning was performed, and the model was hosted on the TogetherAI platform (San Francisco, USA)." (Wrightson et al., 2025, p. 4)
> ![[wrightsonGPTRCTsUsing2025-evd-p4-2.png]]

### Who?

> **Models / participants:** Meta **Llama 2 70B** (the version available on TogetherAI in mid-2024; specific Llama 2 weights snapshot not disclosed). No human evaluators in this EVD; Schulz et al. 2020 labels serve as ground truth, and the GPT-4-correct subset of TRAIN serves as the fine-tuning supervision.
>
> **Sample-size flow:** identical paper denominator to the GPT-4 EVD, 160 Schulz et al. papers → 113 included after extraction/access exclusions → split 80/20 TRAIN/TEST stratified by paper section.
>
> **Fine-tuning input:** the GPT-4-correctly-answered subset of TRAIN text-question pairs (size not separately reported; Table 1 lists pre-split per-question pair counts of 108–113, so TRAIN ≈ 80% of those; not all TRAIN pairs were used, only those GPT-4 answered correctly).
>
> **Evaluation set:** the **20% TEST split** restricted to **8** CONSORT questions (question 9 excluded → 8 questions × ~20% of 108–113 papers per question), with each paper analysed in 3 sections (Introduction / Method / Results) due to context-window limits.
>
> "The limit on the size of data (the 'context window') submitted to Meta's Llama 2 (Menlo Park, California, USA) AI models meant that entire papers could not be analysed. Instead, we followed the example of Liu and Shah and divided each paper into three sections: the introduction, method and results." (Wrightson et al., 2025, p. 2)

## Other Notes

- This is essentially **GPT-4-distilled Llama 2**: the fine-tuning labels are GPT-4 outputs, not human labels. The fine-tuned Llama 2 (F1 = 0.84) approaches but does not reach GPT-4 Turbo (F1 = 0.89) on the same TEST split.
- The +0.21 F1 improvement (0.63 → 0.84) is substantial but the authors do not report a paired significance test; CIs on accuracy overlap weakly (64% (57–71%) vs. 83% (77–88%)).
- Default TogetherAI hyperparameters (temperature=0.7, Top P=0.7) are notably higher / more stochastic than the GPT-4 Turbo settings used elsewhere in the same paper (temperature=0.2, Top P=0.2). The authors do not justify the asymmetry.
- The Llama 2 evaluation excludes CONSORT question 9 (effect sizes), the question on which GPT-4 performed worst (F1 = 0.57), so the Llama 2 numbers are not strictly comparable to GPT-4's pooled F1 = 0.89.
